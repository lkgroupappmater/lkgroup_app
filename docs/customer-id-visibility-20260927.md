# 고객 ID 표시 및 검색

- 로그인 직후 앱 공통 상단과 웹 공개/관리 상단에서 고객 고유 ID를 바로 표시한다. 미연결·조회 오류는 번호와 구분하며 새로고침할 수 있다.
- 회원정보, 앱 관리 메뉴, 관리자 회원 목록·회원 수정창에 같은 번호를 표시한다. 회원 검색은 고객 ID도 인식한다.
- 이름/수취인 입력에서 `23`, `023`, `ID 023`으로 고객 ID를 검색한다. 웹 화물·고객 현황 검색에도 연결 ID를 사용한다. 일반 문자 검색은 유지한다.
- `9023`은 실제 고객 ID 9023으로 검색하며, 명세서 구분용 9 접두어를 임의로 제거하지 않는다.
- 고객 ID 검색은 기존 역할별 화물 열람 범위를 유지한다. ID 조건을 행 수 제한 전에 적용하므로 최근 일반 검색 1,000건 밖의 고객 화물도 검색할 수 있다.
- 기존 고객/화물/명세서 값이나 엑셀 수식은 변경하지 않는다. 아직 고객과 매칭되지 않은 회원에게 번호를 임의로 발급하지 않는다.

검증: 신규 ID 표시/계정 전환/재시도/검색 테스트, 기존 관련 웹·API 테스트, 실제 DB 읽기 전용 검색과 service_role 권한 검사 통과. 웹 관리자 통합 테스트는 기존 기준본과 동일한 엑셀 관련 실패 4개이며 이 변경에서 추가된 실패는 없다. 앱 테스트·빌드·네이티브 실행은 배포 CI에서 확인한다.

추가 고객 정리 화면 개선:
- 이름 클릭은 해당 이름 검색, 전화번호 클릭은 뒤 4자리 검색으로 연결한다. 검색 시 비교 범위를 제한하던 중복/불일치 필터를 해제하고 기존 선택 항목은 유지한다.
- 검색·필터·일괄 처리 도구와 페이지 버튼은 고정하고 고객 목록만 스크롤한다. 웹 팝업은 넓히고 고객 행은 간결하게 표시한다.
- 웹에서 수정·일괄 처리·통합·연결 수정이 끝나면 현재 선적/회원 ID 메타데이터를 갱신한다. 연속 처리의 오래된 응답이 최신 ID를 덮어쓰지 않도록 보호한다.
- 검사 시점에 이미 통합된 고객 ID 51개에서 이전 ID에 남은 선적 연결/별칭은 0개였다. 통합 대상 35개 고객의 연결 선적 1,474개가 ID 검색 결과와 모두 일치했다. 고객 원본이나 명세서/엑셀 값은 이 검사에서 수정하지 않았다.
