# 2026-09-28 고객 ID 표시 및 발행 명세서 보존

- 고객 ID를 `LK 0068`처럼 4자리로 표시합니다. 내부 고객 ID와 검색·병합 연결은 유지합니다.
- 새 항차의 일반 명세서는 `LKS 0068` / `LKA 0068`, 수취인 불명·추가 문구로 분리한 명세서만 `LKS 9068` / `LKA 9068`로 표시합니다. 숫자를 잘라 기존 ID와 충돌시키지 않습니다.
- 2026년 해상 09항차까지, 항공 18항차까지는 기존 발행 번호를 유지합니다. 이후 항차부터 고객 ID 번호를 사용합니다.
- 기존 항차는 같은 고객 ID에 여러 발행 번호가 있어도 합치지 않습니다. 앱·웹·엑셀에서 발행 번호와 고객 ID를 별도로 보여주며 수동 번호 및 개별 잠금 기능은 유지합니다.
- 과거 항차의 엑셀 번호 자동 복귀는 막고, 새로 받은 엑셀의 원번호 기준으로 변경 사항을 검토합니다. 기존 관리자 승인 및 자료 잠금은 유지합니다.
- 이전 번호 전환 이력 9건의 화물 4,351행을 원번호로 복원했습니다. 화물 내용, 고객 ID 연결, 금액·할인·배송 자료 보존을 트랜잭션에서 검증했고 원번호 불일치는 0건입니다.

검증: 기존 번호별 엑셀 그룹 분리, 일반·특수 4자리 형식, 번호 경계 정책, 과거 항차 자동 번호 변경 차단, 기존 고객 ID 검색 테스트.

## 오프라인 Excel 적용

- 단독 명세서 양식도 원본 고객명·연락처 입력란에서 고객 ID를 매칭하고 기존 번호 셀에 관리 시트의 적용 번호를 연결합니다. 기존 금액·운임 계산과 인쇄 영역은 유지합니다.
- 기존 자동 정렬 보조열이 없는 화물 양식에도 고객 ID·번호 수식을 연결합니다.
- 오프라인은 다운로드 시점의 고객 정보를 사용합니다. 새 고객 ID는 업로드 후 서버에서 발급하고 최신 파일에 반영하며, 수정된 번호·잠금·배송 확인은 기존 업로드·승인 절차로 동기화합니다.
- 수식 계산 검증: 일반 → 특수 → 수동 → 잠금 → 미매칭 입력 변경 결과 확인. 보호된 고객 이름은 자동 통합하지 않습니다.
