# 해상·항공 배송 시트 원본 유지 (2026-11-13)

## 적용 범위

- 한국→라오스 해상(`kr_la_sea`)과 항공(`kr_la_air`) BASE의 `지방배송`·`시내배송` 시트 전체를 최근 업로드 원본으로 공유한다.
- 업체 선택지·미사용 업체·빈 입력칸·행 순서·행 높이·열 너비·병합·스타일·선택 수식을 유지한다. 공유 문자열과 스타일 ID는 대상 workbook에 맞게 변환하며 VBA 시트 codeName은 대상 값을 유지한다.
- 배송 표를 복사한 다음 기존 공통 DB의 최신 선택 업체·주소를 반영한다. DB에서만 추가한 고객은 기존 입력 공간 배정 규칙을 따른다.
- 운임·화물·명세서·VBA는 다른 경로에서 복사하지 않는다. 특정 항차에 별도 업로드된 엑셀은 기존 항차 원본을 사용한다.

## 원본 수명과 동시성

- `shipment_excel_base_templates.policy_summary.common_delivery_layout`에 업로드 원본을 기록하고 상대 경로도 재생성 대상으로 큐에 넣는다.
- 서버가 재생성한 BASE는 원본 포인터를 바꾸지 않는다. 이후 해상 또는 항공의 새로운 BASE 업로드가 두 경로의 공통 원본을 갱신한다.
- 마이그레이션 `20261113042548_preserve_shared_delivery_layout.sql`은 공용 운영 DB에 한 번 적용했다. 앱 저장소에는 같은 이력을 보관하며 재실행하지 않는다.
- BASE 업로드와 검증된 생성본 커밋은 기존 공통 advisory lock을 같은 순서로 사용한다.

## 처리 및 검증

- 기존 인증된 exporter → identity preparation → finalizer 파이프라인을 사용한다. identity 단계가 원본을 서버 내부에서 읽는다. 중간 streamed ZIP에 원본 ZIP을 중첩하지 않는다.
- 최종 파일에는 내부 컨텍스트나 원본 첨부가 남지 않아야 하며, 수식 그룹 검사와 저장 후 재다운로드 내용 검증을 통과해야 배포된다.
- `shared_delivery_layout` 검증 기록에 원본 참조와 복사한 시트의 행 수·병합 수를 남긴다.
- 합성 회귀 검증: 업체 대안/빈칸/순서/스타일·번호 충돌, 타 시트/VBA 보존, 업로드 방향 전환, 재생성 원본 오염 방지, 인증과 내부 컨텍스트 제거.
- 기존 실제 XLSM 두 개로 로컬 복사 검증: 시트 값/수식/행 구조 일치, 다른 시트와 VBA 바이트 일치, 공유 수식 오류 0. 이 파일들은 테스트용 개인 자료이며 저장소에 포함하지 않는다.

## 앱·웹 반영

앱과 웹은 기존 `export-shipment-excel` API와 공용 DB를 사용한다. 응답 계약은 유지되고 검증 정보만 추가된다. 새 BASE 다운로드에 적용되므로 이번 서버 변경에 새 Android/iOS 설치본은 필요하지 않다. 이미 내려받은 오프라인 엑셀은 다시 다운로드해야 한다.

앱 저장소의 Excel 서버 소스는 현재 운영 중인 3단계 처리 패키지와 맞췄다. Flutter UI, 로그인, 권한 규칙은 변경하지 않았다.
