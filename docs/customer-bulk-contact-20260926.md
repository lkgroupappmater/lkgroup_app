# 2026-09-26 고객 ID 일괄 처리 및 연락처 저장

## 변경 사항

- 앱·웹 고객 ID 목록에 개별 체크박스, 현재 페이지 전체 선택, 선택 개수, 선택 해제를 추가했다. 페이지와 검색을 바꿔도 최대 100개 선택을 유지한다.
- 선택 항목의 ID·이름·연락처를 한 화면에서 수정해 한 번에 저장한다. 변경 사유는 선택 사항이다.
- 선택 ID 비교·통합에서 전체 공통 대상 또는 각 행의 남길 ID를 지정한다. 여러 독립 그룹을 동시에 통합하고 살아남는 고객의 이름·연락처도 같은 작업에서 수정할 수 있다.
- 통합은 그룹별 동일 고객 확인 후 저장하며, 연락처나 통합 대상을 바꾸면 확인 체크가 해제된다. 고정 ID 001·002는 유지한다.
- 서버는 선택된 모든 고객의 최신 버전을 검사하고 단일 DB 트랜잭션으로 처리한다. 충돌·잘못된 그룹·중복 제약 오류가 발생하면 일부 저장 없이 전체 취소한다. 실패 시 화면 입력은 보존한다.

## 연락처 저장 오류 원인

고객 수정 함수가 번호를 바꾸지 않아도 번호 시퀀스의 setval을 호출했으나, 실제 서버 역할(service_role)에 UPDATE 권한이 없어 전화번호 수정도 실패했다. 해당 시퀀스에 필요한 권한만 부여했다. 로그인 사용자나 익명 사용자에게 직접 변경 권한을 추가하지 않았다.

## 검증 및 범위

- 서버 Node 테스트 16개와 관련 웹 UI 테스트 17개 통과.
- 실제 service_role로 여러 연락처 변경, 오래된 버전 차단, 제약 실패 전체 롤백, 두 독립 그룹 통합, 연결 자료·별칭 이동, 순환 대상 차단, RPC 권한을 확인했다. 검증 트랜잭션은 전체 rollback했다.
- 앱 연락처 일괄 저장 및 통합 확인·실패 입력 보존 위젯 테스트를 기존 배포 CI에 추가했다.
- 앱 기준 22d2b9a 및 웹 기준 e3a55d3 이후 요청 기능과 관련 검사만 변경했다. 다른 작업 및 기존 송장 처리 동작은 보존했다.
- 관리자 선택 없는 실제 고객 통합은 실행하지 않았다.

## 사용 순서

고객 ID 관리 → 필요한 고객 체크 → 선택 항목 일괄 수정 또는 선택 ID 비교·통합 → 값 수정 / 남길 ID 지정 → 통합 내용 확인 → 선택 항목 한 번에 저장.
