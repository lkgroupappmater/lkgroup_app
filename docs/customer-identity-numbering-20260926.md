# 고객 고유 ID와 수취인 불명 명세서 구분

## 지금 적용

- `수취인 불명 / 이름`의 고객 ID는 `/` 뒤 실제 이름 기준으로 조회한다. 공백 변형과 앞에 추가된 표기도 같은 규칙을 적용한다.
- 이름·전체 전화번호 또는 확인된 별칭의 정확한 조합을 우선한다. 같은 이름이 여러 고객이면 임의 선택하지 않는다. 유일한 이름으로 연결되어도 전화번호 차이는 불일치 검토로 남긴다.
- `A/B`가 하나의 등록 이름이면 전체 이름을 우선한다. 전체 이름이 없을 때 첫 이름을 사용하는 경우는 전화번호까지 일치해야 한다.
- `???`, `*` 등 식별 불가능한 이름에는 새 고객 ID를 발급하지 않는다. 정상 고객을 찾지 못한 불명 자료도 미연결 상태를 유지한다.
- 기존 불명 ID 11개의 행·연결·감사 이력은 그대로 보관한다. 자동 병합과 기존 연결 삭제는 실행하지 않았다. 공통 조회 계층에서 실제 고객 ID를 해석하고, 별도 고객 선택 목록에서는 불명 이름을 제외한다.
- 회원 가입·승인 시 이름과 전화번호가 기존 고객과 일치하면 같은 고객 ID로 연결한다. 기존 회원도 본인 ID를 읽을 수 있다. 미매칭 회원은 임의 번호를 만들지 않는다.
- 앱·웹 회원정보에 `고객 고유 ID`와 새로고침을 표시한다. 이 표시 기능으로 화물 열람 권한을 추가하지 않는다.

## 향후 명세서 번호 전환 준비

고객 고유 ID와 명세서 구분값은 별개다. 예를 들어 고객 023은 일반 자료에서 023, 수취인 불명 자료에서는 9023을 사용한다. 3자리보다 긴 ID는 자르지 않는다(1234 → 91234).

공통 읽기 전용 `customer_registry_statement_mapping`에는 화물 ID, 경로·연도·항차, 기존 명세서 번호, 원문 이름·연락처, 연결 고객 UUID·번호·이름·연락처, 불명 여부, 명세서용 구분값이 있다. 향후 고객 ID 시트는 이 연결 기준과 확인된 별칭을 사용한다.

고객 ID 정리가 끝난 뒤 별도 전환 작업에서 `LKA/LKS + 고객 ID` 번호를 적용한다. 지방배송·시내배송·선결제·고정 고객 등 기존 그룹 우선순위를 먼저 유지하고 각 그룹 안의 고객 ID를 숫자 오름차순으로 정렬한다. 수식, 금액·할인·VAT, 셀 서식, 인쇄, 화물 순서 로직은 보존한다. 일반 ID와 9 접두 구분값이 겹치는 경우 전환을 중단하고 번호 규칙을 확정해야 한다.

이번 작업에서는 기존 명세서 번호와 엑셀 BASE·수식·정렬을 바꾸지 않았다. 실제 화물 4,351건 전체 원문 해시가 적용 전후 같음을 확인했다.

## 검증

- 서버 18개 및 관련 웹 19개 테스트 통과: 자기 ID 조회, 위조한 타인 ID 무시, 일반 회원의 운영 API 차단, 로그아웃 이후 지연 응답 폐기, 미매칭 표시.
- DB 트랜잭션을 rollback하여 접두어·마스킹·동명이인 구분, 9 접두값, 불명 입력 시 신규 ID 미발급, 일반 회원의 기존 ID 연결, service_role의 자기 ID 조회를 검증했다.
- 앱 고유 ID 표시·미매칭·회원 전환 시 지연 응답 차단 위젯 검사를 배포 CI에 추가했다.
