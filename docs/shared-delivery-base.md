# 한국→라오스 해상·항공 BASE 배송 공통화

## 공통 규칙

BASE 파일의 지방배송·시내배송 정보와 배송 색상은 `kr_la_sea`와 `kr_la_air`에 함께 적용한다. App/Web은 같은 Supabase RPC와 테이블을 사용한다. 태국 육로 등 다른 경로의 배송 DB는 통합하지 않는다.

- 전체 이름과 전화번호가 같은 항목은 최신 BASE 값을 채택한다. 이름이 다른 고객을 같은 원본 번호라는 이유로 합치지 않는다.
- 두 경로 모두 지방배송 90건, 시내배송 16건으로 통합했다. 기존 배송 ID 210개를 유지하고 상대 경로에 없던 항목만 추가했다.
- 배송정보와 배송 색상 외의 운임·할인·선공유·Zone 기준은 해당 경로의 기존 처리를 유지한다.
- 실제 항차 파일의 변경은 해당 경로·연도·항차에만 저장한다. 기존 항차 예외와 화물·명세서 번호는 유지한다.
- 관리자의 배송정보 직접 편집도 해상·항공에 함께 적용한다. 고객이 다른 오래된 BASE 번호 충돌은 최신 BASE 다운로드 안내와 함께 전체 저장을 거부한다.
- 배송 시트가 누락된 업로드는 배송 기준을 유지한다. 명시된 빈 배송 목록 및 삭제는 두 경로에 반영되므로 최신 BASE에서 확인한다.
- 같은 고객의 배송 ID와 기존 API 권한을 유지한다. 공통 잠금으로 BASE 업로드·직접 편집·항차 비교의 동시 처리를 정리한다.
- Excel 생성 시 기존 고객 블록을 먼저 확보한 뒤 번호를 배정한다. 공통화 대상 외 경로의 입력 블록은 삭제하지 않는다.

## 운영 적용

- 공유 DB에 `20261113020352_synchronize_kr_la_sea_air_delivery_base.sql`을 2026-11-13 02:03 UTC에 적용했다. 양쪽 저장소에 동일 SQL을 기록하며 다시 실행하지 않는다.
- 내부 함수의 기존 권한을 유지한다. 앱·웹이 사용하는 `import_excel_workbook_policy`의 authenticated/service_role 실행 권한은 변경하지 않았다.
- 서버 `prepare-shipment-identities` v3 / `export-shipment-excel` v115의 공유 모듈을 일치시켰다.
- 다른 경로 11개는 최초 exporter 114 배포 전 저장 파일로 복구했다. 매일 재생성된 직전 파일 대신 원본 이력과 저장 객체 존재를 확인해 복구했다. 파일을 삭제하지 않았으며 각 BASE의 `policy_summary.restoration`에 복구 이력을 남겼다.
- BASE 자동 재생성은 DB revision에 따라 실행한다. 완료 여부는 `excel_base_sync_state`의 revision=completed_revision, status=ready, stored_download_verified, shared_formula_errors=0으로 확인한다.

## 검증

DB·웹·Excel 회귀 테스트 122개 통과. 실제 DB에서 두 경로의 배송 필드 차이 0건, 기존 ID 210개 유지, 항차별 예외 changes JSON 변경 0건, 공용 API 권한 유지, 복구 이력 11개를 확인했다. 실제 고객 사본은 저장소에 포함하지 않았다.

모바일 단말 반영은 패치 다운로드와 앱 재실행 여부에 따라 달라진다. 서버 데이터 동기화, 웹 배포, Android 패치 배포, 실제 기기 적용 상태를 구분해 보고한다. iOS 서명·스토어 배포는 이 작업에 포함하지 않는다.
